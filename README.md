# СПОТ

[Открыть сайт](https://hokaggee.github.io/spot-site/)

Публичный просмотр через GitHub Pages: видео, анимация, снимок афиши и
опубликованных альбомов. Админка и автоматическое обновление данных работают
в серверной версии. [Как обновить публикацию](docs/github-pages.md).

Главная: видео с логотипом → автоматическая афиша Qtickets + Яндекс Афиши → фотоальбомы → контакты.
Редактор фотографий: `/admin`.

## Запуск на своём сервере

Нужен Python 3.11+ и Pillow. Сборка frontend не требуется.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage_admin.py --username admin
.venv/bin/python server.py --port 8081
```

Откройте `http://127.0.0.1:8081/admin` и войдите по заданным логину и паролю.
Редактор: название вечеринки → дата → фотографии → обложка → публикация.
Можно добавлять новые фотографии в существующий альбом, менять обложку,
удалять отдельные кадры и скрывать альбом с главной. Количество фотографий
в альбоме не ограничено. Один файл — JPEG, PNG или WebP до 40 МБ и 40 Мп.
Загрузка последовательная, с отображением результата каждого файла.
После истечения сессии повторный вход продолжает незавершённую пачку в
том же открытом окне. После закрытия вкладки уже загруженные кадры остаются
в черновике; оставшиеся файлы нужно выбрать снова.

## Общий доступ

Разместите приложение за HTTPS reverse proxy, который передаёт исходный Host.
Задайте `SPOT_ORIGIN=https://ваш-домен`. Создайте доступ через `manage_admin.py`
до первого запуска сервера.
Запустите `server.py --host 127.0.0.1 --port 8081`; проксируйте домен на этот порт.
Не раздавайте корень проекта отдельным статическим сервером: только server.py
защищает исходники, базу, черновики и оригиналы.

Для nginx потребуется `client_max_body_size 41m` и `proxy_read_timeout 300s`
для больших ZIP-альбомов. Долговременное хранение оригиналов требует диска
достаточной ёмкости; программного ограничения количества кадров нет.

Данные сохраняются в `.spot-data/` (SQLite, оригиналы, миниатюры и кэш афиши).
Для другого диска используйте `--data-dir /абсолютный/путь`.
Сохраняйте резервные копии всей этой папки вместе с закрытым файлом доступа.

## Вход в админку

Логин, соль и PBKDF2-хеш пароля хранятся в `.spot-data/admin-auth.json`.
Пароль открытым текстом не сохраняется. Файл создаётся с правами 0600,
исключён из Git и не выдаётся HTTP-сервером. В HTML/JS данных входа нет.
Для хранения вне проекта задайте `SPOT_AUTH_FILE=/закрытая/папка/admin-auth.json`
одинаково для `manage_admin.py` и `server.py`, либо используйте `--file` и `--auth-file`.

Сменить доступ: `.venv/bin/python manage_admin.py --username admin --replace`.
Пароль вводится скрыто и не попадает в аргументы процесса. Флаг `--generate`
создаёт случайный пароль и показывает его один раз. Смена файла завершает
старые сессии, включая входы в момент смены пароля. Регистрация через браузер
отключена. Старый пароль из SQLite переносится в закрытый файл с логином `admin`.

## Источники афиши

Сервер обновляет два публичных источника раз в 15 минут в независимых потоках:

- Qtickets: `https://blagoveshensk.qtickets.events/`, все страницы каталога,
  только площадки «СПОТ», «Спот», «НК СПОТ».
- Яндекс Афиша: `https://afisha.yandex.ru/blagoveshchensk/concert/places/spot-blagoveshchensk`,
  структурированные данные JSON-LD расписания именно этой площадки.

На каждой карточке указан продавец, кнопка ведёт на его исходную страницу события.
Повторы между площадками объединяются по дате, названию без служебных слов и
близкому времени (до 90 минут). При совпадении сохраняется существующая карточка
Qtickets с её временем и ценой. Отдельные сеансы одного источника сохраняются.
Разные концерты и даты не объединяются. События других площадок не добавляются автоматически. Подтверждённые владельцем
переносы перечислены в серверном `event-sources.json`: точная ссылка события,
срок действия подтверждения и причина. Например, Fortuna 812 перенесён в СПОТ,
хотя общая карточка Яндекса ещё указывает Jigger Pony. Его название, оригинальная
афиша и расписание подгружаются с самой страницы Яндекса, покупка ведёт туда же.
Точное локальное время берётся из расписания страницы, а не из её ошибочного
JSON-LD timestamp. После указанной даты исключение автоматически прекращается.

Постеры загружаются напрямую без дополнительного перекодирования: максимальная
опубликованная версия Qtickets и оригинал Яндекса. Полные пропорции сохраняются.
Токены организаторов не нужны. Яндекс иногда ограничивает автоматические запросы;
при недоступности источника или изменении разметки его последний успешный результат
остаётся в кэше, состояние обновления показывается на главной. Поломка одного
источника не блокирует другой. Предыдущий кэш Qtickets переносится автоматически.

Нужен исходящий HTTPS к двум источникам и их CDN. При сбое системного DNS
Яндекса используется резервный запрос DNS-over-HTTPS к `dns.google`; TLS-проверка
сертификата Яндекса остаётся включённой, IP-адреса не закрепляются в коде.

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check app.js
node --check admin.js
```

`tests/browser-flow.js` и `tests/browser-recovery.js` — сценарии для Playwright
browser-run-code. Они используют отдельный локальный тестовый сервер на 8082
с отдельной папкой данных, не рабочие альбомы.

Локальная проверка выполнена с комплектным Python/Pillow Codex. Рабочая версия
на 8081 использует отдельные данные входа содержит добавленные по просьбе владельца демоальбомы для оценки дизайна.

`tests/browser-event-sources.js` проверяет продавцов и ссылки покупки;
`tests/browser-posters.js` — полные качественные постеры на 8081.

## Варианты анимации входа

Сравнение четырёх вариантов: `/assets/loader-preview.html`. Полноэкранный просмотр,
повтор, замедление и переход к настоящему первому экрану сайта. Это отдельная
страница для сравнения. На главной установлен вариант 1 — сборка логотипа.
Проверки: `tests/browser-loader-previews.js` и HTTP-тесты разрешения preview-frame.

Сборка логотипа и красная звезда проигрываются при каждой перезагрузке
главной, включая адреса с #events/#place. Длительность — около двух секунд,
затем открывается сайт. Прежние отметки посещения в localStorage не используются.
Одинаковое поведение на мобильном и широком экране. Есть выход по Escape;
при reduced motion и в демонстрационном iframe интро пропускается.
Проверки: `tests/browser-entry-loader.js`, `tests/browser-mobile-entry.js`.

По просьбе владельца опубликованы 10 демоальбомов по 6 изображений из имеющихся
фотографий и кадров клубного видео. Они отмечены «· демо». Их ID и источники
сохранены в `.spot-data/demo-albums.json`, чтобы затем убрать только демоданные.
Существующие альбомы сохранены. Открытие, просмотр оригинала, скачивание и
обложки на мобильной ширине проверены.
